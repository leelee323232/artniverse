# Demo 未完成功能提示方案

## 本次範例（feature/block-admin）

目前套用於後台「創作者清單」與「創作者類別」：新增、編輯、刪除、啟用／停用，以及類別排序均只打開提示，不修改資料。依最新確認，商品管理不阻擋，「新增商品」已恢復原本表單。另已套用企業委託（需求清單、方案設定及舊需求頁）、行銷與內容（活動、優惠碼、貼文）、運費與分潤。列表、詳情、搜尋、篩選及運費試算保留；寫入、審核、排序與儲存只顯示提示，不送請求或保存資料。

元件：`components/common/FeatureUnavailableDialog.tsx`。
範例：`app/admin/creators/page.tsx`、`app/admin/creator-categories/page.tsx`。

```tsx
import { useState } from "react";
import { FeatureUnavailableDialog } from "@/components/common/FeatureUnavailableDialog";

const [featureUnavailableOpen, setFeatureUnavailableOpen] = useState(false);

<Button onClick={() => setFeatureUnavailableOpen(true)}>新增創作者</Button>
<FeatureUnavailableDialog
  open={featureUnavailableOpen}
  onOpenChange={setFeatureUnavailableOpen}
/>
```

頁面只需管理布林開關。標題固定為「功能未完成，敬請期待」，沒有 API、技術或測試說明；支援點擊視窗外空白處、Esc 及「我知道了」關閉，沿用 Radix Dialog 的焦點限制與無障礙標題／說明。

## 選擇原則

- **保留入口＋提示**：網站主要能力、使用者會主動找的功能。點入口即提示，避免填完整表單後才知道不能送出。
- **先隱藏／註解 JSX**：沒有實作的次要動作、假資料帶出的操作、會使使用者以為涉及付款或安全設定的控制項。整組隱藏，不留下空白工具列或無效按鈕。
- **頁面文字說明**：保留純展示頁面時，清楚說明功能尚未開放；不顯示假成功、假餘額、假審核結果或假儲存狀態。
- **正常保留**：真正已串接功能及純前端操作（篩選、頁籤、圖片預覽、返回、取消）。不以統一提示取代正常的缺貨、未登入或 API 錯誤。
- 不在共用 AdminModal 或整個管理後台一律攔截；應在各功能入口控制，避免日後已接好的功能也被擋住。

## 後台建議（待確認後套用）

| 頁面／區域 | 保留入口並顯示視窗 | 適合先隱藏／註解 | 可保留 |
|---|---|---|---|
| 商品管理 | 依使用者最新確認，不套用阻擋 | 不隱藏商品管理操作 | 保留原本新增、編輯、刪除等操作 |
| 商品分類、商品模板 | 新增／編輯分類或模板 | 刪除、啟停、排序；無法真正上傳的檔案控制項 | 展示與篩選 |
| 創作者管理、創作者分類 | 新增／編輯入口 | 刪除、啟停、排序、未串接的頭像上傳 | 列表及詳情瀏覽 |
| 創作者申請審核 | 審核入口或詳情內的審核按鈕 | 已由入口攔截時，假通過／拒絕／重新審核確認流程可隱藏 | 只讀申請資料；無真實資料時顯示空狀態或說明 |
| 商品申請審核 | 審核入口 | 同上，避免假通過或假退件 | 只讀詳情與有真實來源的檔案下載 |
| 活動管理 | 新增／編輯／審核入口 | 刪除、上下架、排序、未串接上傳 | 活動列表、篩選 |
| 貼文管理 | 新增／發布入口 | 刪除、沒有正式上傳的圖片控制項 | 只讀貼文展示 |
| 優惠碼 | 新增／編輯入口 | 刪除、啟用／停用等未串接狀態操作 | 規則展示與篩選 |
| 企業委託與合作方案 | 新增／編輯方案、審核需求入口 | 排序箭頭（目前只部分串接）、刪除、沒有實作的聯繫或報價動作 | 只讀詳情 |
| 運費規則 | 新增／編輯入口 | 啟停及寫入操作 | 試算可留，但不能暗示本地設定已套用正式結帳 |
| 分潤管理 | 儲存比例時提示，或將編輯入口改提示 | 建議先隱藏可編輯欄位、重設與儲存整組，避免誤認會影響真實結算 | 有真實來源的只讀資料 |
| 儀表板 | 無需每個連結都擋；目的頁入口自行處理 | 假營運統計、無來源的績效數字、不會下載的匯出報表 | 導覽與真實統計；未完成的卡片可改為尚未開放 |

隱藏動作也須隱藏或阻擋對應寫入路徑，不能只移除其中一個按鈕卻保留另一個可送出的入口。後續逐頁確認實際串接狀態後再套用，不能只依頁面名稱判定。

## 暫時阻擋與恢復方式

依使用者要求，所有本次被阻擋取代的原始邏輯，已直接保留在對應頁面的註解中，不必查 Git。用 `TEMP:` 或「原始邏輯（暫時停用，請保留）」可找到。

- 處理函式：移除暫時的 `showFeatureUnavailable()`，取消緊接在下方的原始邏輯註解。表單提交保留一次 `e.preventDefault()` 即可。
- 按鈕入口：把 `showFeatureUnavailable` 換回旁邊註解記錄的原始 callback。
- 創作者頁：刪除及啟停函式整段保留為註解；取消註解後，再切回對應入口。
- 貼文入口：將 `onOpenChange` 換回旁邊保留的 `setIsPostModalOpen`，同時恢復發布 handler。
- 優惠碼刪除及分潤重設：原始 inline callback 已就地保留。
- 企業委託排序：原始 handler 內的 API 呼叫與檔頭 import 均有註解保留，恢復時須一起處理。
- 全部阻擋取消後，才移除不再使用的視窗 state、import 及元件；商品管理已恢復，無須再處理。

保留的是原本流程，其中包含示範資料與尚未串接的實作。取消註解前仍需完成串接及驗證，不代表取消阻擋後就具備正式功能。

這次補回註解後，10 個頁面的 TSX 語法檢查及 `git diff --check` 均通過；目前對使用者仍維持原有阻擋行為。
